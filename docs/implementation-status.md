# Статус реализации и проверок

Дата среза: 30.09.2026. Источник истины для функций — код этого коммита; наличие ТЗ или макета не означает реализованный путь. Этот файл связывает API-комплект с требованиями `docs/02-mvp-specification.md` рабочего проекта и с критериями кейса «Эффективный бизнес».

| Область | Требование / приёмка | Фактическое состояние |
| --- | --- | --- |
| Запуск и воспроизведение | AC-13, кейс: одна команда Docker, фикстуры, README | Compose, Dockerfile, `.env.example` и сид есть; README описывает запуск, роли, порты, остановку и проверку. Успешная сборка в этом окружении не подтверждена: Docker Engine недоступен. |
| Меню, варианты, цена | FR-06, AC-05 | Публичное меню и серверный `/menu/quote` есть; API-комплект проверяет латте 350 мл с овсяным молоком за 28 000 коп. Полный сценарий заказа и защита от изменения цены при оплате отсутствуют. |
| Роли и MAX | FR-01–03 | В коде есть проверка `initData`, серверные сессии и администраторы точек. Проверка живого клиента MAX и назначение production тестового администратора остаются ручным этапом. Dev-вход только локальный. |
| Публикация и стоп-лист | FR-05, FR-07 | Черновик и публикация раздельны; стоп-лист проверяется по двум точкам. Воспроизвести через сид и DATA-API. |
| Собственный API | Кейс: OpenAPI 3.0/3.1, DATA-API.yaml, тестовые данные и роли | `openapi.json` сгенерирован из FastAPI (3.1, 89 путей), `DATA-API.yaml` и `test-data/api-demo.json` добавлены. Публичный адрес предоставлен владельцем, но ответ production сервера из этой среды не подтверждён. |
| Предзаказ и ЮKassa | FR-12–24, AC-05–10 | Не реализованы. Демо собирает выбор для кассы, поэтому никаких платёжных или статусных инвариантов не заявляем как выполненные. |
| Сотрудник, отзыв, отчёт | FR-25–30, AC-11–14 | Полный путь оплаченного заказа отсутствует; часть интерфейса аналитики и бот-функций есть, но это не финансовый отчёт и не отзыв после выдачи. |

Перед сдачей команда с доступом к развёртыванию должна: подтвердить `https://max.nii-mvus.ru/api/v1/health/ready`, версию запущенного коммита и опубликованные демо-данные; пройти `DATA-API.yaml`; выдать отдельному тестовому MAX-аккаунту роль администратора; выполнить чек-лист `docs/max-production-check.md` в mobile и web; измерить время Docker-сборки и вписать точный SHA в технический слайд презентации. Секреты и настоящий `initData` в репозиторий не добавлять.

При подготовке API-комплекта OpenAPI успешно выгружена из приложения (3.1, 89 путей), YAML/JSON разобраны и пути сверены со схемой; `docker compose config --quiet` прошёл, frontend собрался и unit-тесты прошли. С использованием доступных локальных пакетов backend дал 151 passed, 54 skipped, 1 deselected; полный прогон не состоялся из-за отсутствия Windows-модулей MCP и локального Tesseract. Браузерный `editor.smoke.cjs` завершился тайм-аутом на ожидании «Ссылка-приглашение». Docker-сборка и production MAX не проверены. По просьбе владельца дальнейшие проверки в этом изменении остановлены; это не подтверждение исправности всего продукта.
