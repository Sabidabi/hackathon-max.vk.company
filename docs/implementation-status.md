# Состояние проекта

Обновлено 30 сентября 2026 года.

«Синица» показывает меню кофейни в MAX и по QR-ссылке. Владелец создаёт точки, назначает им меню, редактирует карточки, размеры и добавки, управляет наличием и оформлением. Изменения проходят через черновик и публикацию. Гость собирает выбор и показывает его на кассе.

«Помощь Синицы» разбирает фото или PDF, готовит карточки по текстовому запросу, проверяет меню и предлагает оформление. Изменения можно просмотреть до применения. MCP-сервер даёт внешнему помощнику ограниченный доступ к черновику меню.

| Область | Готово сейчас | Следующий шаг |
| --- | --- | --- |
| Вход и роли — FR-01–03 | Вход через MAX, проверка доступа на сервере, администраторы заведения | Проверка в мобильном и веб-клиенте MAX |
| Меню и цены — FR-05–07, AC-05 | Черновик, публикация, размеры, обязательные добавки, расчёт цены на сервере в копейках | Проверка на меню пилотной кофейни |
| Точки — FR-05 | Несколько точек, назначение меню, наличие по точкам, QR | Проверка с несколькими реальными точками |
| Предзаказ и ЮKassa — FR-12–24, AC-05–10 | Пока нет | Интервалы самовывоза, оплаченный заказ, отмена и возврат |
| Работа сотрудника и отчёт — FR-25–30, AC-11–14 | Есть аналитика действий с меню; отчёта по оплатам нет | Очередь заказов, статусы выдачи, приватный отзыв, финансовый отчёт |

В последних изменениях сохранена история чата при переходах между разделами, синхронизировано оформление после применения предложения, улучшена проверка карточек от модели, переработана навигация к «Помощи Синицы» и добавлен возврат из редактора и гостевого меню. В переключателе точки одинаковые названия больше не повторяются. Эти изменения относятся к редактированию меню и оформлению в FR-05–07.

У бота есть ответ на первое событие `bot_started` и команду `/start`, но получение такого ответа в рабочем MAX пока не подтверждено. Для проверки подписки на сервере добавлена команда `python -m app.max_api.check_webhook`; порядок проверки и восстановления есть в [инструкции MAX](max-production-check.md).

Проверки: сборка frontend, unit-тесты и браузерные сценарии с тестовым API на 320, 390, 768 и 1280 px. Проверка настоящей модели, доставки сообщений бота и клиента MAX проводится отдельно после обновления сервера. Для демонстрации используйте [сценарий](DEMO.md), для API — [OpenAPI](../openapi.json) и [DATA-API.yaml](../DATA-API.yaml), для развёртывания — [инструкцию MAX](max-production-check.md).
